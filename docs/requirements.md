## 1. 한 줄 소개

결제내역 **캡처만 올리면 AI가 알아서 분류·기록**해 주고,
돈을 많이 쓴 분야를 줄일 수 있는 **청년 정책·대안을 추천**해 주는 대학생 가계부 웹 앱

## 2. 개요

| 항목 | 내용 |
|---|---|
| 목적 | 가계부를 손으로 적는 귀찮음을 없애고, 어디에 돈을 많이 쓰는지 바로 알게 하기 |
| 사용자 | 대학생(청년) |
| 실행 환경 | 웹 앱 (PC + 폰 브라우저, 반응형) |
| 동시 접속자 | 5~10명 (팀원 + 시연) |
| 디자인 | 영수증·통장 콘셉트 (종이색 배경, 포인트 색 1개, Bootstrap 5 기반) |
| 기존 앱과 다른 점 | ① 계좌 연동 없이 캡처만 올리면 됨 ② 대학생에 맞는 카테고리 ③ 내 계좌끼리 보낸 돈은 지출에서 뺌 ④ 많이 쓴 분야에 맞는 청년 정책·대안 추천 |

## 4. 필수 기능 (MVP)

### F0. 회원가입·로그인
- 아이디 + 비밀번호로 가입, 로그인하면 JWT 토큰 발급
- 로그인한 사람은 **자기 내역만** 볼 수 있음

### F1. 계좌·카드 등록
- 내가 쓰는 계좌·카드를 직접 입력: 이름, 은행·카드사, **용도** (예: "생활비 통장", "저축 통장")
- 등록한 **내 계좌끼리 보낸 돈은 지출로 세지 않음** (다른 사람에게 보낸 돈은 지출)

### F2. 캡처 올리면 AI가 분류하고 저장
1. 은행·카드 앱의 결제내역 화면 캡처를 올림 (한 번에 최대 5장, 장당 5MB 이하)
2. AI가 사진에서 **날짜, 가게 이름, 금액**을 읽음
3. 카테고리 분류
   - 전에 고친 적 있는 가게 → 저장된 규칙대로 분류
   - 처음 보는 가게 → AI가 분류
4. **확인 화면**에서 틀린 걸 고침
   - **더치페이**: 사람 수를 입력하면 결제 금액 ÷ 사람 수 = **내 몫만 지출로 기록** (원래 금액도 같이 저장)
   - 날짜와 금액이 같은 내역이 이미 저장돼 있으면 **"이미 저장한 내역 같아요"로 표시** (지울지는 사용자가 고름)
5. 저장 버튼 → DB에 저장. 고친 분류는 **규칙으로 기억**해서 다음부터 자동 적용
- 아주 긴 스크롤 캡처나 5MB가 넘는 캡처는 브라우저에서 줄여서 보냄
- 캡처 사진은 서버에 **저장하지 않음** (읽은 글자만 저장)

### F3. 거래 내역
- 달마다 거래 목록 보기 (날짜, 가게, 금액, 카테고리)
- 카테고리·금액 고치기, 지우기
- 카테고리를 고치면 F2의 규칙에도 반영

### F4. 하루 예산 경고 (홈)
- 설정에서 월 예산과 고정비(구독료, 통신비 등)를 입력
- **오늘 쓸 수 있는 돈** = (월 예산 − 고정비 − 이번 달 어제까지 쓴 돈) ÷ 오늘을 포함한 남은 날짜
- 고정비로 등록한 결제는 "쓴 돈"에서 뺌 (고정비가 두 번 빠지지 않게)
- 오늘 쓴 돈이 80%를 넘으면 노란 경고, 100%를 넘으면 빨간 경고 (화면에 표시)

### F5. 월별 보기
- 이번 달 카테고리별 지출 그래프
- **지난달과 비교**: 카테고리마다 얼마 늘었는지·줄었는지

### F6. 청년 정책·대안 추천 (차별점)
- 이번 달 가장 많이 썼거나 지난달보다 많이 늘어난 카테고리를 찾음
- 그 카테고리를 아낄 수 있는 **청년 정책이나 대안**을 보여 줌
  - 예: 교통비 많음 → K-패스 / 식비 많음 → 천원의 아침밥
- 정책 정보는 팀이 조사해서 `data/policies.json`으로 만듦 (출처 링크 포함)

## 7. API (RESTful, 9강)

| 기능 | 메서드 | 주소 |
|---|---|---|
| 가입 / 로그인 | POST | `/api/auth/signup`, `/api/auth/login` |
| 계좌·카드 | GET, POST | `/api/accounts` |
| | PATCH, DELETE | `/api/accounts/:id` |
| 설정 | GET, PUT | `/api/settings` |
| 캡처 읽기 (저장 안 함) | POST | `/api/scans` |
| 거래 저장 / 목록 | POST, GET | `/api/transactions` (`?month=2026-11`) |
| 거래 수정 / 삭제 | PATCH, DELETE | `/api/transactions/:id` |
| 오늘 예산 | GET | `/api/summary/today` |
| 월별 합계 | GET | `/api/summary/monthly?month=2026-11` |
| 정책 추천 | GET | `/api/recommendations?month=2026-11` |

- 자세한 요청·응답 형식은 `docs/API.md`에 정리 (9강 API 문서화)
- 상태 코드: 생성 201, 조회 200, 삭제 204, 잘못된 요청 400, 로그인 필요 401, 없음 404, 서버 오류 500

## 9. 지켜야 할 것

**보안 (6강, 9강)**
- AI 키, DB 주소, JWT 비밀 키는 `.env`에만 두고 `.gitignore`에 등록
- Never trust the client: 금액·날짜·파일 형식은 서버에서 다시 검사
- 로그인 안 한 요청은 401, 남의 데이터 요청은 거부
- helmet으로 보안 헤더 추가, 캡처 올리기에 Rate Limiting 적용 (AI 요금 폭탄 방지)
- 오류는 중앙 오류 처리 미들웨어에서 한 번에 처리

**개인정보**
- 캡처 사진은 저장하지 않음
- 테스트용 실제 내역은 이름·카드번호·계좌번호를 가리고 사용

**검증 (5강, 6강)**
- 코드: ESLint 경고 0개, `npm audit` 취약점 확인, 단위 테스트
- 화면: 콘솔 오류 0개, Lighthouse 90점 이상, 폰에서 확인
- AI 분류: 테스트 캡처로 정확도 측정 (목표 90%)
