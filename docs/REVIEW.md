# PR 확인하고 합치기 (박영웅)

1학년 PR 하나를 5분 안에 보는 순서예요. (1강 품질 게이트키핑, 11주차 코드 리뷰)

## 합치는 순서

**A → B → C → D → 캡처 인식(`feature/scan`)** 순서로 합쳐요.

- A의 계좌 목록과 B의 저장 API가 있어야 캡처 올리기가 끝까지 돌아가요.
- PR을 하나 합칠 때마다 남은 브랜치에게 `git pull origin main`을 시켜요.

## 합치기 전에 볼 것

1. 자동 검사가 초록색인가?
2. **Files changed**에 담당 파일만 있나? 담당 파일은 README 표에 있어요.
3. 아래 위험한 실수가 없나?
4. 내 컴퓨터에서 받아서 직접 눌러 봤나?

```bash
gh pr checkout PR번호
```

```bash
npm test
```

## AI가 자주 내는 위험한 실수

| 찾을 것 | 왜 위험한가 |
|---|---|
| `find`, `findOne`, `update`, `delete`에 `user: req.userId`가 없음 | 남의 가계부가 보여요 |
| `findById(req.params.id)`로 바로 찾음 | 다른 사람 id를 넣으면 남의 데이터를 고쳐요 |
| `innerHTML`에 사용자 입력을 넣음 | 스크립트 공격(XSS)이 돼요 |
| `req.body`를 그대로 저장 | 금액이나 작성자를 조작할 수 있어요 |
| `package.json`에 새 패키지 | 물어보기로 했어요 |
| API 응답 모양이 `docs/API.md`와 다름 | 다른 사람 화면이 깨져요 |
| 화면에 `mock.js`가 남아 있음 | 진짜 데이터가 안 보여요 |
| 새 색상, 이모지, 숫자 카드 나열 | 디자인이 따로 놀아요 (`docs/DESIGN.md`) |
| 정책 링크가 안 열리거나 내용이 다름 | AI가 지어낸 정책일 수 있어요 |

## 검증 짝

1학년은 짝(A ↔ B, C ↔ D)의 PR을 먼저 읽고 댓글을 달아요. 짝이 확인한 뒤에 내가 승인해요. 짝은 AI가 만든 코드를 사람 눈으로 다시 보는 역할이에요. (10강 Cross-Validator)

## 확인 질문

AI가 쓴 코드는 작성자가 줄마다 설명할 수 있어야 해요. 하나만 골라 물어봐요. 답을 못 하면 AI에게 설명을 받고 다시 답하게 해요.

- 이 API에서 다른 사람 데이터를 어떻게 막았어요?
- 잘못된 값을 보내면 어디서 걸러져요?
- 이 계산이 틀리면 어떤 화면이 틀려져요?

## 합치는 방법

PR 페이지에서 **Add your review → Approve** 후 **Merge pull request**를 눌러요.

내가 만든 PR은 스스로 승인할 수 없어요. 1학년에게 승인을 받거나, 체크 항목을 직접 확인한 뒤 **Merge without waiting for requirements to be met**으로 합쳐요.

## 합친 뒤

- PR 페이지의 **Delete branch**로 합친 브랜치를 지워요. 작성자는 최신 `main`에서 다음 브랜치를 만들어요.

- [TODO](../TODO.md)에 체크해요.
- 전체 기능이 다 합쳐지면 [전체 점검표](QA.md)를 돌려요.
