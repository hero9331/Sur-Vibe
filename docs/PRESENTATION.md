# 12/9 발표 준비

실제 슬라이드는 발표자료 담당이 완성 화면과 진짜 수치로 만들어요. 이 문서는 무엇을 넣고 어떻게 시연할지 정리한 뼈대예요. 발표 시간은 교수님 공지를 확인해서 맞춰요.

**기말 프로젝트는 다른 팀과 비교돼요.** 그래서 ① 끝까지 오류 없이 돌아가는 것 ② 청년 정책 추천을 가장 눈에 띄게 하는 것에 시간을 써요.

## 이야기 순서

| 순서 | 내용 | 보여 줄 것 |
|---|---|---|
| 1 | 문제: 가계부는 귀찮고, 기존 앱은 내 계좌 이체도 지출로 잡음 | 팀 회의에서 나온 불편한 점 |
| 2 | 해결: 캡처만 올리면 끝 + 아낄 방법까지 추천 | 한 줄 소개 |
| 3 | 시연 | 아래 대본 |
| 4 | 차별점: 많이 쓴 분야에 맞는 청년 정책 | 추천 화면, 조사한 정책 수 |
| 5 | 구조 | 브라우저 → Express → MongoDB, Claude API |
| 6 | AI 결과를 어떻게 믿을 수 있게 했나 | 정확도, 확인 화면, 서버 재검사 |
| 7 | 보안과 개인정보 | 캡처 미저장, 데이터 분리, Rate Limit |
| 8 | 협업과 검증 (결정 기록 `docs/DECISIONS.md`를 Q&A 근거로) | 브랜치와 PR, 자동 검사, 시험 수, 수업 내용 반영표(`docs/LECTURE-MAP.md`) |
| 9 | 배운 점, AI가 틀렸던 사례 | 팀원별 한 가지 |

## 역할 분배 (꼭 어필할 것)

교수님이 강조한 부분이에요. **코드는 AI가 쓰고, 사람은 방향을 정하고 검증했다**는 걸 보여 줘요. (10강 Driver, Navigator, Cross-Validator)

| 역할 | 누가 | 하는 일 | 보여 줄 증거 |
|---|---|---|---|
| Driver | AI (Claude Code, Codex) | 지시받은 대로 코드를 씀 | 커밋의 AI 표시(`Co-Authored-By`), AI 규칙 파일 `AGENTS.md` |
| Navigator | 기능 담당자 (1학년 A~D, 캡처 기능은 박영웅) | 무엇을 만들지 정하고 AI에게 지시, 직접 실행해서 확인 | 설명서의 지시문, 담당자 이름의 커밋 |
| Cross-Validator | 검증 짝 (A↔B, C↔D)과 박영웅 | AI가 만든 코드를 읽고 질문, 고칠 점 지적, 승인 | PR 댓글과 승인 기록 |
| 총괄 Navigator | 박영웅 | 구조 설계, API 계약서, 팀 규칙, 합치기, 배포 | `docs/API.md`, `CONTRIBUTING.md`, `docs/DECISIONS.md` |

**프론트·백엔드로 나누지 않고 기능별로 나눴어요.** 한 사람이 자기 기능의 API(백엔드)와 화면(프론트)을 끝까지 맡아요.

- API 계약서(`docs/API.md`)로 경계를 먼저 정해서, 서로 기다리지 않고 동시에 만들 수 있었어요.
- 기능마다 파일을 나눠서 같은 파일을 동시에 고치는 충돌이 없었어요.
- 한 사람이 기능 하나를 끝까지 책임지니, 누구에게 질문이 가도 자기 기능을 설명할 수 있어요.

**발표 때 보여 줄 화면:** PR 하나를 열어서 "AI가 쓴 코드 → 짝의 댓글 → 고친 커밋 → 승인" 흐름을 보여 줘요. 협업 규칙이 실제로 돌아갔다는 가장 확실한 증거예요.

## 발표 전에 채울 숫자

아직 비워 둬요. 측정한 값만 적어요.

| 항목 | 값 | 재는 법 |
|---|---|---|
| 진짜 캡처 카테고리 정확도 | | `npm run eval -- eval/private` |
| 진짜 캡처 금액 정확도 | | 위와 같음 |
| 측정한 거래 수 | | 위와 같음 |
| 캡처 1장 처리 시간 | | 위와 같음 |
| 캡처 1장 요금 | | Anthropic 콘솔 사용량 ÷ 장수 |
| 자동 시험 수 | | `npm test` |
| 조사한 정책·대안 수 | | `data/policies.json` |
| Lighthouse 점수 | | 배포 주소에서 측정 |
| 팀원 커밋, PR 수 | | GitHub Insights |

가짜 캡처 점수(`eval/RESULTS.md`)는 글자가 또렷해서 잘 나와요. 발표에는 진짜 캡처 점수를 써요.

## 시연 대본 (3분)

준비: 발표용 아이디를 미리 만들고, 지난달과 이번 달 내역을 넣어 둬요. 가짜 캡처 `eval/samples/`를 폰이나 노트북에 넣어 둬요.

1. 홈: "오늘 쓸 수 있는 돈이 얼마인지 바로 보여요."
2. 올리기: 가짜 캡처 1장을 올려요. "캡처만 올리면 AI가 읽어요."
3. 확인 화면: 카테고리 하나를 고치고 더치페이 2명을 넣어요. "AI가 틀릴 수 있어서 저장 전에 사람이 확인해요."
4. 저장 → 내역: "고친 분류는 기억해서 다음부터 자동으로 적용돼요."
5. 월별: "지난달보다 배달비가 늘었어요."
6. 추천: "그래서 이 분야를 아낄 수 있는 청년 정책을 추천해요." 링크를 열어 진짜 정책임을 보여 줘요.

## 시연이 망가졌을 때

| 상황 | 대비 |
|---|---|
| 강의실 인터넷이 안 됨 | 폰 핫스팟을 켜 둠 |
| AI가 느리거나 실패 | 같은 시연을 **녹화한 영상**으로 바로 넘어감 |
| API 크레딧 부족 | 발표 전날 콘솔에서 잔액 확인 |
| 서버가 처음에 느림 | 발표 5분 전에 앱을 한 번 열어 둠 |
| 로그인 실패 | 발표용 계정 2개를 미리 로그인해 둠 |

진짜 결제내역, 이름, 번호, API 키, `.env` 창이 화면에 나오지 않게 해요. 시연용 브라우저를 따로 켜요.

## 예상 질문

| 질문 | 답의 방향 |
|---|---|
| AI가 틀리면 어떻게 해요? | 저장 전 확인 화면, 고친 분류 기억, 서버 재검사, 측정 정확도 |
| 결제내역은 안전해요? | 사진은 저장 안 함. 다만 읽기 위해 AI 서비스로 전송됨을 솔직히 말함. 이름과 번호 가리기 안내 |
| 왜 계좌 연동을 안 했어요? | 마이데이터 허가가 필요해서 학생 팀은 불가. 캡처 방식이 우리 답 |
| 캡처에 이상한 명령이 있으면요? | 프롬프트 인젝션 시험을 했고, 답은 정해진 형식만 받아 재검사함 |
| 돈이 많이 들지 않나요? | 측정한 장당 요금, 사람별 시간당 30회 제한 |
| 정책 정보는 믿을 수 있어요? | AI가 답하지 않고 팀원이 공식 출처를 확인한 목록 |
| 같은 내역을 또 올리면요? | 날짜와 금액으로 찾아 표시하고 사용자가 고름 |
| 내 기능 코드 설명해 주세요 | 각자 `START-HERE` 6번 질문으로 준비 |
| AI가 다 한 거 아닌가요? | AI가 틀렸던 사례와 시험, PR 확인으로 잡아낸 것 |
