# 개인정보, AI 사용, 라이선스

결제내역을 다루는 AI 앱이라 팀이 지키기로 한 내용이에요. (수업계획 12주차 보안과 윤리)

## 데이터가 어디로 가나요?

| 데이터 | 가는 곳 | 저장 |
|---|---|---|
| 캡처 사진 | 우리 서버 메모리 → Claude API | 우리 서버와 DB에 **저장하지 않음** |
| 읽어 낸 날짜, 가게, 금액, 카테고리 | 사용자가 확인하고 저장을 누르면 DB | MongoDB Atlas |
| 내 계좌 이름 | 내 이체를 구분하려고 Claude API에 전달 | MongoDB Atlas |
| 비밀번호 | 서버에서 bcrypt로 암호화 | 암호화한 값만 저장 |

캡처는 외부 AI 서비스(Anthropic)로 전송돼요. 그래서 사용자에게 이름과 번호를 가리도록 안내하고, 카드번호와 계좌번호는 읽어 적지 않도록 AI에게 지시해요.

이 앱은 수업 과제예요. 시연과 테스트에는 가짜 내역이나 가린 캡처만 써요. 다른 사람의 내역을 동의 없이 올리지 않아요.

## AI가 틀릴 때를 대비한 장치 (환각 대응)

| 위험 | 대응 |
|---|---|
| 금액이나 가게를 잘못 읽음 | 저장 전에 사람이 확인하고 고치는 화면을 둠 |
| AI 답의 형식이 이상함 | 서버에서 날짜, 금액, 카테고리를 다시 검사하고 틀린 건 뺌 |
| 없는 거래를 만들어 냄 | 정답지가 있는 캡처로 정확도를 측정 (`eval/`) |
| 캡처 안의 글이 AI에게 명령함 (프롬프트 인젝션) | 캡처 속 지시를 따르지 않게 지시하고, 지시문이 든 캡처로 시험 |
| 없는 청년 정책을 지어냄 | 정책은 AI가 답하지 않음. 팀원이 공식 출처를 직접 확인해 파일로 관리 |
| AI가 만든 코드의 보안 구멍 | 자동 시험, ESLint, `npm audit`, 사람의 PR 확인 |

## AI를 어디에 썼나요?

코드와 문서 작성에 Claude Code와 Codex를 썼어요. 결과물의 책임은 팀원에게 있어요.

- 기능마다 담당자가 AI에게 지시하고, 직접 실행해 확인한 뒤 자기 이름으로 커밋해요.
- 커밋에 AI 표시(`Co-Authored-By`)가 있는 건 지우지 않아요.
- 모든 코드는 PR에서 사람이 확인한 뒤 합쳐요.
- 발표에서도 AI를 쓴 부분과 사람이 검증한 부분을 나눠서 말해요.

## 표절과 저작권

- 은행이나 카드 앱의 로고와 화면을 가져다 쓰지 않아요. 시험용 캡처는 일반적인 화면으로 직접 만들었어요.
- 정책 설명은 출처 문장을 복사하지 않고 한 줄로 요약하고, 링크를 함께 적어요.
- 다른 코드를 참고하면 PR에 출처를 적어요.
